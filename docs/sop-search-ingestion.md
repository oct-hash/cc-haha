# 搜索→入库 SOP（强制执行）

> 完整工作流：体检 → 内部查重 → 外部搜索 → 筛选 → 去重 → 结构化入库 → 关联校验 → 输出清单。
> 违反规则 3/5/8 会导致 90% 的重复劳动和无声丢失。
>
> 本 SOP 经过 7 轮压测验证（2026-07-29），4 次问题发现 + 4 次修复迭代。
> CLAUDE.md 中保留紧凑检查清单；本文档是权威完整版。

---

## 阶段 1：搜索前（必须执行，不可跳过）

### 规则 1 — 体检

后台运行 `agent-reach doctor --json`（timeout 30s），不阻塞后续步骤。
不可用时按 retry chain 处理，找不到可用后端时告知用户，不得瞎猜命令。
doctor 未完成不影响后续搜索 —— 优先用已知可用的后端（Exa/GitHub CLI 等零配置通道）。

### 规则 2 — 先搜内部知识库（双通道）

在调外部搜索前，必须用双通道检查已有内容：

1. `mcp__gbrain__search`（关键词 FTS）— 对缩写、英文术语、精确匹配可靠
2. `mcp__gbrain__query`（语义混合搜索）— 对意译、长句查询可靠

**两个都用，不可只依赖一个。** 任一通道命中相关页面即视为"已有内容"。
如果已有相关内容，直接引用 gbrain 结果，不再重复搜索。
仅在两个通道都无结果或用户明确要求"最新/外部/补充"时才启动外部搜索。

> **压测教训 (Test #5)**: 旧版只用 `query`（语义搜索）— 对 "Claude Code MCP" 返回空，
> 但 `search`（关键词）正确找到 5 个重叠页面。单通道有静默失效风险。

---

## 阶段 2：搜索约束

### 规则 3 — 搜索预算（硬限制 + 跨语言例外）

单次任务：外部搜索 ≤ 3 次 + 平台 ≤ 3 个。
**跨语言例外**：中英文/多语言调研可放宽至 ≤ 5 次搜索，但必须在回复中标注 `🌐 跨语言例外`。
超过预算时，必须停下来列出已找到的内容，让用户决定是否继续搜。

> **压测教训 (Tests #3, #4)**: 跨语言场景 100% 超预算。中英文内容分布在不同平台，
> 一次搜索无法同时覆盖。

### 规则 4 — 结果筛选（分层）

每批搜索完成后，按两层筛选：

**核心入库** ≤ 5 条（写入 gbrain 正文）：
- 内容直接回答用户问题（不是泛泛相关）
- 来源可信（官方文档 > 学术论文 > 技术博客 > 论坛帖子）
- 不重复（同一内容的不同转载只保留原始出处）
- 互补性：每条覆盖不同角度

**延伸阅读** ≤ 3 条（写入页面底部"延伸阅读"小节，不入正文）：
- 高质量但不直接回答核心问题
- 相关但角度已被核心引用覆盖

丢弃的链接不在回复中列出（减少噪音）。

> **压测教训 (Test #4)**: 20 条全高质量时筛选感觉随意。
> 分层后核心与延伸各有定位，减少主观判断。

---

## 阶段 3：入库规范（写入 GBrain）

### 规则 5 — 去重检查（两步）

**R5a — slug 碰撞检查**：
`mcp__gbrain__put_page` 之前必须 `mcp__gbrain__search` 查同名 slug。
已存在的页面用 `mcp__gbrain__put_page` 更新（覆盖），不要新建重复页面。

**R5b — 内容语义去重**（修复 Test #7 盲区）：
`put_page` 前，用新页面的 **title + 摘要** 跑一次 **双通道** `mcp__gbrain__search` + `mcp__gbrain__query`：
- 命中高相关页面 + 同角度 → **更新已有页面**，不新建
- 命中高相关页面 + 不同角度 → 新建 + `add_link` 互相 cross-link
- 无命中 → 正常新建

> **修复历史 (Test #10)**: R5 原先只检查 slug，Test #7 确认了语义重复盲区。
> R5b 在 `put_page` 前用 title+摘要做双通道搜索，关闭了这个盲区。
> 代价：每次入库多 2 次调用（search + query）。
>
> **双通道必要性 (Test #10 发现)**: `query`（语义）对 "OAuth PKCE MCP" 返回空，
> 但 `search`（关键词）正确发现重叠。R2 和 R5b 都必须用双通道，单通道会静默失效。

### 规则 6 — 结构化写入格式

每条入库内容必须包含 frontmatter + 以下字段：

```yaml
---
tags: [research, topic-name, source-type]
source: <原始 URL>
date: <发布日期或抓取日期>
---
# 标题

## 摘要
<3-5 句内容概述>

## 关键发现
- 发现 1
- 发现 2

## 来源
- [原始链接](URL)
```

禁止：无 frontmatter、无 source、空 content 的页面写入。

### 规则 7 — 关联校验

`mcp__gbrain__put_page` 成功后：
1. `mcp__gbrain__get_links` 确认页面链接完整
2. 如有相关已有页面，`mcp__gbrain__add_link` 建立关联
3. 写入失败时必须告知用户，不得静默跳过

---

## 阶段 4：收尾

### 规则 8 — 输出入库清单（必须）

任务结束时必须输出清单，格式：

```
📦 本次入库 (X 条)：
1. [标题] → gbrain slug: [slug] | 来源: [URL]
2. [标题] → gbrain slug: [slug] | 来源: [URL]
❌ 未入库 (Y 条)：
- [标题]: [原因]
```

不得无声入库。用户必须知道什么东西进了知识库。

## 反模式速查

| 错误行为 | 正确做法 |
|---------|---------|
| 跳过 doctor 直接搜 | 后台 `agent-reach doctor --json`，30s 超时不阻塞 |
| 只用 query 不用 search 查 gbrain | **双通道**: `mcp__gbrain__search` + `mcp__gbrain__query` 都用 |
| 搜了 5+ 次还不停 | 普通 3 次/跨语言 5 次后停下请求用户指示 |
| 结果全量 dump 不入库 | 筛选后结构化写入 gbrain（核心 ≤5 + 延伸 ≤3） |
| 入库后不写清单 | 规则 8 格式输出 |
| 重复建同名页面 | R5a slug 碰撞 + R5b 双通道 title/摘要语义去重 |
| R5b 只用 query 不用 search | **双通道**：query 在 3 次压测中均静默失效（#5/#8/#10），search 全部命中 |

---

> **⚠️ 已知系统性问题**: `mcp__gbrain__query`（语义混合搜索）在 10 轮压测中有 3 次静默失效
> （Test #5 "Claude Code MCP"、Test #8 "Claude Code MCP server development"、Test #10 "OAuth PKCE MCP"），
> 而 `mcp__gbrain__search`（关键词 FTS）在相同查询中全部正确命中。
> **结论**: 语义搜索不得作为任何去重路径（R2 或 R5b）的唯一通道。所有去重必须双通道。
