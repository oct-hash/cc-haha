# 文档写作指南

## 核心原则：自然散文优先

默认使用自然段落叙述，结构和格式服务于内容而非装饰。

### 推荐的写法

- 自然段落推进论证
- 必要时使用标题分隔章节层级
- 技术文档中合理使用代码块
- 用段落叙述表达复杂逻辑

### 避免的写法

- 大量加粗/斜体做装饰
- 列表嵌套超过 2 层
- 每个段落配一个小标题
- 用表格替代简单叙述
- emoji 作为装饰元素
- 每个句子单独一行（bullet-point 伪装成散文）

## 文档类型风格指南

### 技术文档
- 清晰 > 优美
- 用代码示例辅助说明
- 不过度使用格式装饰
- 操作步骤用编号，概念说明用段落

### 分析报告
- 论证流畅，用段落推进逻辑
- 用列表总结要点，不用于构建论证
- 数据支持论点
- 标注信息来源

### 创意写作
- 匹配用户语气和风格
- 保持文学性而非格式化
- 段落长度有节奏变化

### 学术写作
- 正式但不做作
- 引用必须标注来源
- 参见 `citation-format` 技能

### 日常对话
- 以普通文本回应
- 不滥用结构化格式
- 拒绝请求时不使用列表

## 格式使用检查

每次文档输出前：
- [ ] 我是否在可以用段落的地方用了列表？
- [ ] 是否有超过 2 层嵌套的列表？
- [ ] 是否有不必要的加粗/斜体？
- [ ] 排版是否服务于内容而非装饰？
