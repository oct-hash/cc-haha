# CSO Review

从首席安全官视角进行安全审查。关注数据保护、访问控制和合规性。

## 使用方法

`/cso` - 审查当前代码库安全问题
`/cso [功能描述]` - 审查指定功能的安全问题

## 审查流程

### Step 1: 资产识别

识别需要保护的资产：
- 用户数据（个人信息、认证信息）
- 业务数据（财务、交易）
- 系统资产（密钥、证书、配置）
- 第三方服务依赖

### Step 2: 威胁建模

**STRIDE 威胁模型：**

| 威胁类型 | 描述 | 例子 |
|---------|------|------|
| Spoofing | 身份伪装 | 窃取认证 token |
| Tampering | 数据篡改 | 修改请求参数 |
| Repudiation | 否认行为 | 删除审计日志 |
| Information Disclosure | 信息泄露 | 暴露用户数据 |
| Denial of Service | 服务拒绝 | DDoS 攻击 |
| Elevation of Privilege | 权限提升 | 普通用户变管理员 |

### Step 3: 安全检查

#### 认证与授权
- [ ] 密码强度要求是否足够？
- [ ] 是否有 MFA 支持？
- [ ] Session 管理是否安全？
- [ ] 权限控制是否最小化？

#### 数据保护
- [ ] 敏感数据是否加密？
- [ ] 传输层是否使用 TLS？
- [ ] 密钥管理是否安全？
- [ ] 审计日志是否完整？

#### 输入验证
- [ ] 所有用户输入是否验证？
- [ ] 是否有 SQL 注入防护？
- [ ] 是否有 XSS 防护？
- [ ] 文件上传是否安全？

#### API 安全
- [ ] API 认证机制？
- [ ] Rate limiting 是否实现？
- [ ] CORS 配置是否正确？
- [ ] 敏感端点是否保护？

### Step 4: 合规性检查

**检查要点：**
- GDPR（欧盟用户数据）
- CCPA（加州用户数据）
- HIPAA（医疗数据）
- SOC2（安全控制）

## 安全问题分级

| 级别 | 说明 | 处理 |
|------|------|------|
| CRITICAL | 立即修复，可能导致数据泄露 | **阻塞发布** |
| HIGH | 需要修复，可能被利用 | **本次修复** |
| MEDIUM | 应该修复，提高安全性 | **计划修复** |
| LOW | 建议修复 | **后续迭代** |

## 安全最佳实践

1. **纵深防御**: 不要依赖单一安全措施
2. **最小权限**: 只授予必要的权限
3. **默认安全**: 安全应该是默认行为
4. **持续监控**: 实时监控安全事件
5. **快速响应**: 建立安全事件响应流程
