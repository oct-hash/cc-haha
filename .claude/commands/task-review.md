# Task Review 命令

当用户输入「任务完成」时，系统自动执行任务复盘，分析本次工作过程中工具使用的合理性，并输出迭代改进建议。

## 触发条件

当用户输入以下内容时触发：
- 「任务完成」
- 「/task-review」
- 「复盘」

## 复盘流程

### Step 1: 收集工具使用记录

从当前会话上下文中提取所有工具调用记录：

1. 统计使用的工具类型及调用次数
2. 记录每个工具的用途和效果
3. 识别工具使用的顺序和依赖关系

### Step 2: 工具使用合理性评估

对每个使用的工具进行评估：

| 评估维度 | 说明 |
|---------|------|
| 必要性 | 该工具是否必须使用？是否有更简单的替代方案？ |
| 时机 | 工具使用的顺序是否合理？是否有前置依赖遗漏？ |
| 效率 | 是否存在重复调用或可以合并的调用？ |
| 正确性 | 工具参数是否正确？调用方式是否恰当？ |

### Step 3: 检查漏用和错用

分析以下问题：

**漏用检查：**
- 是否遗漏了应该使用的工具？（如：应该先 Read 再 Edit）
- 是否跳过了必要的验证步骤？
- 是否缺少错误处理？

**错用检查：**
- 工具选择是否不当？
- 参数是否错误？
- 是否用 Bash 做了更适合用 Edit 处理的事？

### Step 4: 生成复盘报告

输出结构化复盘报告：

```markdown
# 任务复盘报告

## 基本信息
- 复盘时间：[当前时间]
- 任务类型：[功能开发/Bug修复/重构/文档/其他]
- 会话工具调用总数：X 次

## 工具使用统计

| 工具类型 | 调用次数 | 主要用途 |
|---------|---------|---------|
| Read | X | 读取文件内容 |
| Edit | X | 修改代码 |
| Bash | X | 执行命令 |

2. [具体问题] → [建议方案]
```

## 评估标准

### 工具选择合理性

| 场景 | 推荐工具 | 避免 |
|------|---------|------|
| 查看文件内容 | Read | Bash(cat) |
| 小幅修改 | Edit | Write (全量覆盖) |
| 创建新文件 | Write | Bash(echo) |
| 执行命令 | Bash | - |
| 搜索代码 | Grep | Bash(grep) |
| 搜索文件 | Glob | Bash(find) |

### 工具使用顺序

```
正确顺序示例：
1. Read（了解现状）
2. Grep（搜索相关代码）
3. Edit（进行修改）
4. Bash（验证/测试）

错误顺序示例：
1. Edit（未了解现状就修改）
2. Read（修改后才发现问题）
```

### 常见错误模式

1. **未 Read 就 Edit**：未了解文件当前内容就进行修改
2. **重复 Read**：同一文件读取多次，中间无修改
3. **Bash 替代工具**：用 `cat`、`ls`、`find` 等 Bash 命令替代专用工具
4. **跳过验证**：修改后未执行测试/构建验证
5. **工具嵌套**：在 Bash 中调用本应用的能力

## 输出要求

1. 复盘报告必须包含所有 7 个部分
2. 每个评估项必须有具体事例支撑
3. 迭代建议必须具体可执行
4. 最终总结控制在 3 句话以内

## 特殊处理

- 如果会话极短（工具调用 < 3 次），简化为快速复盘
- 如果发现严重问题（工具错用导致错误），标记为「需要回滚」
- 如果工具使用完全正确，标记为「最佳实践」
