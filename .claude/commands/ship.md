# Ship

从 DevOps 视角执行安全部署。确保发布过程可控、可靠。

## 使用方法

`/ship` - 开始部署流程
`/ship --dry-run` - 预览部署步骤
`/ship --rollback` - 回滚到上一版本

## 部署流程

### Step 1: 部署前检查

**必须检查：**
- [ ] 代码审查已通过
- [ ] 所有测试通过
- [ ] 安全扫描通过
- [ ] 配置已更新
- [ ] 变更日志已记录

**通知相关方：**
- [ ] 团队成员
- [ ] 运维团队
- [ ] 客服团队（如需要）

### Step 2: 环境准备

**检查目标环境：**
- [ ] 生产环境可访问
- [ ] 必要的 credentials 配置
- [ ] 监控和告警就绪
- [ ] 回滚计划已准备

### Step 3: 执行部署

**部署方式选择：**

| 方式 | 适用场景 | 风险 |
|------|---------|------|
| 蓝绿部署 | 无状态服务 | 低 |
| 金丝雀发布 | 有重大变更 | 中 |
| 滚动更新 | 持续交付 | 低 |
| 直接部署 | 紧急修复 | 高 |

**执行步骤：**
```bash
# 1. 创建备份
./scripts/backup.sh

# 2. 拉取最新代码
git pull origin main

# 3. 执行数据库迁移（如有）
npm run migrate

# 4. 构建
npm run build

# 5. 部署
./scripts/deploy.sh --env=production

# 6. 验证
./scripts/health-check.sh
```

### Step 4: 部署后验证

**健康检查：**
- [ ] 服务启动正常
- [ ] 关键端点响应
- [ ] 数据库连接正常
- [ ] 日志无错误

**业务验证：**
- [ ] 核心功能可用
- [ ] 性能指标正常
- [ ] 错误率未增加

### Step 5: 监控发布

**部署后 15 分钟内：**
- [ ] 错误率监控
- [ ] 延迟监控
- [ ] 资源使用监控
- [ ] 用户反馈监控

## 回滚流程

**触发条件：**
- 错误率显著上升
- 关键功能不可用
- 性能严重下降

**回滚步骤：**
```bash
# 1. 停止部署
./scripts/deploy.sh --stop

# 2. 执行回滚
./scripts/rollback.sh

# 3. 验证回滚
./scripts/health-check.sh

# 4. 通知团队
```

## 部署原则

1. **小步快跑**: 频繁发布，每次变更小
2. **自动化**: 减少人工干预，降低错误
3. **可回滚**: 每次部署都能回滚
4. **监控先行**: 部署前确保监控就绪
5. **值班准备**: 部署期间有人值班
