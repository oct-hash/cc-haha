# GSD Discuss

在 GSD 流程的 Discuss 阶段，捕获关键实现决策并记录到 STATE.md。

## 使用方法

`/gsd-discuss [决策问题]`

或直接输入决策内容，系统将引导你完成决策过程。

## 决策流程

### Step 1: 澄清问题

明确你要做的决策：
- **问题是什么？** 清晰地描述要解决的问题
- **有哪些选项？** 列出所有可能的方案
- **谁来做决定？** 你（用户）还是我（Agent）？

### Step 2: 分析选项

对每个选项分析：
- **优点**: 这个方案的优势
- **缺点**: 这个方案的劣势
- **风险**: 可能带来的风险
- **成本**: 实施难度和时间

### Step 3: 做出决定

基于分析选择最佳方案，或请用户确认。

### Step 4: 记录决策

将决策记录到 STATE.md：

```markdown
## 决策记录

### [日期] - [决策标题]
- **问题**: [要解决的问题]
- **选项分析**:
  - 选项A: [优点/缺点]
  - 选项B: [优点/缺点]
- **决策**: [选择的方案]
- **原因**: [决策的理由]
- **负责人**: [谁负责]
- **截止时间**: [YYYY-MM-DD]
```

## 决策类型

### 技术决策
- 架构选择（微服务 vs 单体）
- 技术栈决策（React vs Vue, TypeScript vs JavaScript）
- 性能优化方案
- 安全策略

### 产品决策
- MVP 范围
- 用户故事优先级
- 验收标准
- 发布策略

### 流程决策
- 代码审查流程
- 测试覆盖率要求
- 部署策略

## 示例

```
用户: /gsd-discuss 是否需要实时通知功能？

讨论:
• 选项A: WebSocket - 实时性好，实现复杂
• 选项B: Server-Sent Events - 简单，单向
• 选项C: 轮询 - 实现简单，实时性差

决策: 选项B (SSE)
原因: MVP阶段，单向通知足够，实现简单

已记录到 STATE.md
```

## 注意事项

1. **每决策一事**: 一个 `/gsd-discuss` 只处理一个决策
2. **记录原因**: 记录决策理由便于后续回顾
3. **设置deadline**: 关键决策设置完成时间
4. **定期回顾**: 在里程碑检查点回顾决策是否仍然有效
