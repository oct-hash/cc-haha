# GSD Plan

在 GSD 流程的 Plan 阶段，将决策转化为可执行的计划。

## 使用方法

`/gsd-plan [任务描述]`

如果当前没有 STATE.md，系统会引导你创建。

## 计划流程

### Step 1: 理解目标

明确要计划的任务：
- **用户需求是什么？** 描述用户的实际需求
- **验收标准是什么？** 如何判断任务完成？
- **约束条件有哪些？** 时间、技术、资源限制

### Step 2: 研究探索

在实现之前，先研究：
1. **GitHub 搜索**: 查找现有实现和模式
2. **库文档**: 确认 API 使用方式
3. **项目内搜索**: 查找可复用的代码

### Step 3: 任务分解

将大任务拆分为小任务：

```
Plan.md 结构：

## 目标
[具体可衡量的目标]

## 任务列表

### Phase 1: [阶段名]
- [ ] 任务1.1
- [ ] 任务1.2

### Phase 2: [阶段名]
- [ ] 任务2.1
- [ ] 任务2.2

### Phase 3: [阶段名]
- [ ] 任务3.1
- [ ] 任务3.2
```

### Step 4: 验证计划

检查计划完整性：
- [ ] 每个任务都有清晰的交付物
- [ ] 任务之间没有循环依赖
- [ ] 关键路径上的任务已标识
- [ ] 有可衡量的完成标准

### Step 5: 写入文件

将计划保存到 `PLAN.md`（项目根目录）

## PLAN.md 模板

```markdown
# Plan: [任务名称]

## 目标
[具体可衡量的目标描述]

## 验收标准
- [ ] 标准1
- [ ] 标准2

## 时间线
- 开始日期: YYYY-MM-DD
- 预计完成: YYYY-MM-DD

## 任务详情

### Phase 1: 准备
- [ ] [任务]
- [ ] [任务]

### Phase 2: 核心实现
- [ ] [任务]
- [ ] [任务]

### Phase 3: 验证
- [ ] [任务]
- [ ] [任务]

## 风险与备选方案
| 风险 | 影响 | 备选方案 |
|------|------|---------|
| [风险1] | [影响] | [备选] |

## 依赖
- 外部依赖: [依赖]
- 内部依赖: [依赖]
```

## 示例

```
用户: /gsd-plan 实现用户注册功能

系统:
1. 引导确认需求（邮箱/手机号，用户名密码）
2. 研究现有用户相关的代码模式
3. 分解任务
4. 生成 PLAN.md
```

## 注意事项

1. **先研究后计划**: 不要在研究之前就开始写代码
2. **任务可执行**: 每个任务都应该可以独立执行
3. **标识依赖**: 明确标识任务间的依赖关系
4. **设置里程碑**: 将大任务分成多个里程碑
