# GSD Ship

在 GSD 流程的 Ship 阶段，完成发布并更新里程碑。

## 使用方法

`/gsd-ship` - 开始发布流程
`/gsd-ship --dry-run` - 预览发布步骤

## 发布流程

### Step 1: 最终检查

执行发布前的最终检查：

```
□ 所有 P0/P1 问题已修复
□ 测试覆盖率 >= 80%
□ 代码审查通过
□ 文档已更新
□ 变更日志已记录
```

### Step 2: 创建 PR

使用 prp-pr 或手动创建 PR：

1. **整理提交**: 确保提交历史清晰
2. **编写 PR 描述**: 包含变更内容和测试结果
3. **关联里程碑**: 在 PR 中引用相关里程碑

PR 描述模板：

```markdown
## 变更摘要
[简要描述变更]

## 变更详情
- [ ] 功能1
- [ ] 功能2

## 测试结果
- 单元测试: 通过 (X%)
- 集成测试: 通过
- E2E 测试: 通过

## 验证结果
[验证命令和结果]

## 后续工作
[计划的后续迭代]
```

### Step 3: 合并代码

在 PR 通过审查后：
1. 合并到目标分支
2. 触发部署流程（如有）
3. 验证部署成功

### Step 4: 更新里程碑

更新 `.claude/milestones.json`：

```json
{
  "milestones": [
    {
      "id": "ms-001",
      "name": "用户认证系统",
      "status": "completed",
      "startDate": "2026-06-01",
      "endDate": "2026-06-03",
      "completionRate": 100,
      "deliverables": [
        "用户注册 API",
        "登录/登出功能",
        "密码重置"
      ]
    }
  ]
}
```

### Step 5: Archive 完成的工作

1. 将 PLAN.md 移动到 `.claude/plans/archived/`
2. 更新 STATE.md 进入下一里程碑
3. 清理已完成的临时文件

### Step 6: 启动下一里程碑

如果存在下一里程碑：
1. 创建新的 STATE.md
2. 更新当前里程碑信息
3. 开始 Discuss 阶段

## 注意事项

1. **不要跳过检查**: 即使时间紧迫，最终检查不能跳过
2. **小步发布**: 尽量小步迭代，每次发布一个完整功能
3. **记录经验**: 在发布后总结经验教训
4. **及时庆祝**: 完成里程碑后适当庆祝 🎉
