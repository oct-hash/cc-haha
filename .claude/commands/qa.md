# QA

从 QA 专家视角进行测试验证。确保产品质量符合发布标准。

## 使用方法

`/qa` - 运行完整 QA 流程
`/qa [模块名]` - 测试指定模块

## QA 流程

### Step 1: 测试计划审查

检查是否有测试计划：
- 单元测试覆盖范围
- 集成测试场景
- E2E 测试用例
- 性能测试基准

### Step 2: 功能验证

**手动测试清单：**

#### 核心功能
- [ ] 主要用户流程测试
- [ ] 边界条件测试
- [ ] 错误处理测试
- [ ] 空状态测试

#### 用户交互
- [ ] 表单验证
- [ ] 按钮状态
- [ ] 加载状态
- [ ] 错误提示

#### 兼容性
- [ ] 浏览器兼容性
- [ ] 设备兼容性
- [ ] 屏幕尺寸适配
- [ ] 字体渲染

### Step 3: 质量检查

**代码质量：**
- [ ] 测试覆盖率 >= 80%
- [ ] 无重大代码异味
- [ ] 性能达标

**用户体验：**
- [ ] 关键路径流畅
- [ ] 错误信息友好
- [ ] 帮助文档完整

### Step 4: 缺陷管理

**缺陷分级：**

| 级别 | 说明 | 处理 |
|------|------|------|
| P0 | 功能完全不可用 | **阻塞发布** |
| P1 | 功能部分损坏 | **本次修复** |
| P2 | 体验问题 | **计划修复** |
| P3 | 优化建议 | **后续迭代** |

## 测试场景示例

### 认证流程
```
场景: 用户注册
步骤:
1. 输入有效邮箱和密码
2. 点击注册按钮
3. 验证邮箱
4. 完成注册

预期: 用户成功注册并跳转至首页
```

### 支付流程
```
场景: 购买商品
步骤:
1. 添加商品到购物车
2. 点击结算
3. 选择支付方式
4. 完成支付

预期: 订单创建成功，库存减少，邮件通知发送
```

### 错误场景
```
场景: 网络中断
步骤:
1. 开始文件上传
2. 断开网络
3. 恢复网络

预期: 显示错误提示，允许重试
```

## QA 原则

1. **测试驱动质量**: 质量内建于产品，而非测试出来
2. **风险导向**: 重点测试高风险区域
3. **用户视角**: 从用户角度思考，而非代码视角
4. **持续集成**: 自动化测试是质量门禁
