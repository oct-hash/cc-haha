# Plan Eng Review

从首席工程师视角审查架构决策。确保技术选择支持长期目标。

## 使用方法

`/plan-eng-review` - 审查 PLAN.md 中的架构决策
`/plan-eng-review [架构描述]` - 审查指定架构

## 审查流程

### Step 1: 架构概览

了解整体架构：
- 系统的核心组件
- 组件之间的关系
- 数据流和依赖

### Step 2: 关键决策审查

对每个架构决策审查：

#### 可扩展性
- 系统能处理 10x 增长吗？
- 数据库扩展策略是什么？
- 是否有单点故障？

#### 可维护性
- 代码库组织是否清晰？
- 是否有适当的抽象？
- 技术债务水平如何？

#### 安全性
- 是否有安全设计原则？
- 敏感数据如何处理？
- 是否有审计日志？

#### 性能
- 关键路径的延迟是多少？
- 是否有性能瓶颈？
- 如何监控性能？

### Step 3: 技术选型评估

**评估每个技术选型：**

| 维度 | 问题 |
|------|------|
| 成熟度 | 这个技术是否经过验证？ |
| 社区 | 社区活跃度如何？ |
| 支持 | 如果出问题，能获得支持吗？ |
| 招聘 | 市场上有足够的相关人才吗？ |
| 锁定 | 是否会被这个技术锁定？ |

### Step 4: 风险识别

**技术风险矩阵：**

```
                难以修复      容易修复
            ┌─────────────┬─────────────┐
        高  │   重点关注   │   风险缓解   │
      风 险  │             │             │
            ├─────────────┼─────────────┤
        低  │   观察      │   可接受    │
      风 险  │             │             │
            └─────────────┴─────────────┘
```

## 工程问题清单

### 架构原则
- [ ] 架构是否符合模块化原则？
- [ ] 是否有清晰的数据流？
- [ ] API 设计是否一致？

### 可扩展性
- [ ] 水平扩展策略是什么？
- [ ] 数据库设计支持增长吗？
- [ ] 缓存策略是什么？

### 可靠性
- [ ] 是否有故障隔离？
- [ ] 错误处理是否完善？
- [ ] 是否有超时和重试机制？

### 性能
- [ ] 关键路径延迟目标？
- [ ] 如何处理峰值负载？
- [ ] 监控和告警策略？

### 安全
- [ ] 认证和授权策略？
- [ ] 数据加密方案？
- [ ] 安全审计机制？

## 决策准则

1. **简单原则**: 不要过度设计
2. **YAGNI**: 你不需要它 - 现在不需要
3. **可逆性**: 优先选择可逆决策
4. **增量演进**: 设计支持渐进式改进的架构
