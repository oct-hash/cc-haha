# GSD Verify

在 GSD 流程的 Verify 阶段，验证交付物并生成修复计划。

## 使用方法

`/gsd-verify` - 验证当前里程碑的所有交付物
`/gsd-verify [模块名]` - 验证指定模块

## 验证流程

### Step 1: 读取交付清单

从 PLAN.md 读取验收标准：
- 每个任务的交付物
- 验收标准的完成定义
- 测试覆盖率要求

### Step 2: 功能 Walkthrough

逐项验证功能交付：

```
验证清单：
□ 功能1: [描述] - [验证方法]
□ 功能2: [描述] - [验证方法]
□ 功能3: [描述] - [验证方法]
```

验证方法：
- **直接测试**: 运行功能并观察结果
- **单元测试**: 运行相关测试套件
- **集成测试**: 运行端到端测试
- **代码审查**: 检查实现是否合理

### Step 3: 问题分类

将发现的问题分类：

| 级别 | 说明 | 处理 |
|------|------|------|
| P0 | 功能完全不可用 | **阻塞** - 立即修复 |
| P1 | 功能部分损坏 | **高优先级** - 本次修复 |
| P2 | 体验问题 | **中优先级** - 记录待修复 |
| P3 | 优化建议 | **低优先级** - 后续迭代 |

### Step 4: 生成修复计划

对于发现的问题，生成修复计划：

```markdown
## 修复计划

### P0 - 功能完全不可用
1. [问题描述]
   - 原因: [分析]
   - 修复: [修复方案]
   - 负责人: [谁负责]
   - 截止: [时间]

### P1 - 功能部分损坏
1. [问题描述]
   - ...
```

## 验证检查清单

### 代码质量
- [ ] 代码符合编码规范
- [ ] 无 hardcoded secrets
- [ ] 错误处理完善
- [ ] 单元测试覆盖 >= 80%

### 功能完整
- [ ] 所有计划功能已实现
- [ ] 验收标准全部满足
- [ ] 用户场景测试通过

### 性能安全
- [ ] 无明显性能问题
- [ ] 安全漏洞已修复
- [ ] 敏感数据正确处理
