# GSD Execute

在 GSD 流程的 Execute 阶段，按照计划执行任务。

## 使用方法

`/gsd-execute` - 从 PLAN.md 读取任务并开始执行
`/gsd-execute [任务编号]` - 执行指定任务

## 执行流程

### Step 1: 读取计划

从 `PLAN.md` 读取任务列表，识别：
- 当前可执行的任务（无依赖阻塞）
- 关键路径上的任务
- 可以并行执行的任务组（waves）

### Step 2: Wave 执行

将任务分组为 waves，每个 wave 内的任务可以并行执行：

```
Wave 1: [任务1.1, 任务1.2]  ← 无依赖，可以并行
   ↓
Wave 2: [任务2.1]  ← 依赖 Wave 1
   ↓
Wave 3: [任务3.1, 任务3.2]  ← 无依赖，可以并行
```

### Step 3: 执行任务

对每个任务：
1. **理解要求**: 明确任务的交付物
2. **先研究**: 搜索现有实现和模式
3. **TDD**: 先写测试，再实现
4. **自检**: 对照检查清单自检
5. **更新状态**: 完成后更新 STATE.md

### Step 4: 更新进度

执行完成后：
- 更新 STATE.md 中的任务状态
- 记录执行过程中发现的问题
- 识别需要额外研究的问题

## Wave 示例

```
当前 Wave: Wave 2
├── 任务2.1: 实现用户注册 API ✓ 已完成
├── 任务2.2: 添加输入验证 ✗ 进行中
└── 任务2.3: 编写单元测试 ○ 等待中

进行中:
• [Edit] 添加 Zod 验证 schema
• [Bash] 运行测试验证
```

## 执行原则

### 并行执行
- 独立任务并行执行以提高效率
- 使用多个 Agent 并行处理不同任务
- 注意工具使用的并行性

### 上下文管理
- 每个 wave 结束后总结关键发现
- 识别需要持久化到记忆的信息
- 避免上下文膨胀

### 质量保证
-遵循 TDD 方法论
- 及时运行测试验证
- 代码审查后进入下一任务

## STATE.md 更新格式

```markdown
## 执行记录

### Wave 2 (2026-06-03 14:00-15:30)
- [x] 任务2.1 - 10分钟
- [x] 任务2.2 - 25分钟
- 发现: 需要额外处理密码强度验证

## 进行中的任务
- [ ] 任务2.3
```

## 注意事项

1. **一个 wave 一总结**: 每个 wave 结束后总结关键发现
2. **更新状态**: 及时更新 STATE.md 中的进度
3. **识别阻塞**: 发现阻塞立即上报
4. **上下文清理**: 每个 wave 完成后清理上下文
